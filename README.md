# MeetMatch — AI-сервис умного нетворкинга

Подсказывает участнику IT-мероприятия, с кем стоит познакомиться и почему. По анкете за несколько миллисекунд выдаёт 5 человек, у каждого — объяснение в 1–2 предложениях и готовая первая фраза. Учитывается взаимность целей: ищущему работу показываем только тех, кто нанимает.

Трек: **AI for Digital Economy & Smart Business**.

- [Открыть MeetMatch и заполнить анкету](https://meetmatch-metu.streamlit.app/) · [Демо для жюри, 30 секунд](https://dalya28.github.io/meetmatch/demo/) · [Презентация](demo/MeetMatch.pdf) · [Сценарий питча](docs/10-pitch.md) · [Отчёт QA](docs/08-test-report.md)

### Дополнительный режим Claude

Задайте `MEETMATCH_AI=1` и `ANTHROPIC_API_KEY` в окружении процесса или корневых строковых параметрах Streamlit Secrets. По умолчанию AI выключен. Модель задаётся через `MEETMATCH_MODEL` (по умолчанию `claude-haiku-5-5`). После локальной выдачи сервис отправляет только структурированные профессиональные признаки и временные номера 15 кандидатов. Проверенный ответ обновляет пять карточек. При таймауте или ошибке остаётся базовая выдача.

Для платного сравнения запустите `python scripts/evaluate_claude.py` с ключом в окружении. Скрипт сравнит обе версии на одной разметке и покажет долю размеченных рекомендаций. В Community Cloud выберите Python 3.11, ветку main и файл app.py.

## Как выполнены требования

| Требование | Где сделано |
|---|---|
| Анкета: роль, стек, опыт, интересы, «о себе», цель из 6 вариантов | `app.py`, форма слева |
| Топ-5 с объяснением в 1–2 предложениях | `matcher.py` → `explain()`, шаблоны в `texts.py` |
| Взаимность целей | `taxonomy.GOAL_MATCH`: жёсткий фильтр до оценки |
| Рабочий интерфейс | веб-страница на Streamlit |
| База 100+ синтетических анкет | `scripts/generate_profiles.py` → 276 анкет, проверка `scripts/validate_data.py` |
| **Should:** казахский, русский, английский | переключатель языка; объяснения, первая фраза и интерфейс на трёх языках; текст «о себе» распознаётся на всех трёх |
| **Should:** первая фраза для знакомства | `matcher.icebreaker()`, кнопка «копировать» |
| **Should:** «познакомились / не подошло» и пересчёт | кнопки на карточке; «не подошло» убирает человека и понижает похожих |
| **Could:** расписание встреч 1:1 | `plan_meetings()`: каждая встреча в ближайший общий свободный слот, без накладок |
| **Could:** дашборд организатора | спрос и предложение по целям, карта интересов зала, популярный стек, подсказки |
| **Could:** стенды партнёров | `recommend_booths()`, 2 стенда под анкету |

## Как работает подбор

Своя модель не обучается: используются правила и TF-IDF, поэтому подбор мгновенный и объяснимый.

1. **Взаимность целей.** Сначала оставляем только тех, чья цель отвечает вашей:

   | Ваша цель | Кого показываем |
   |---|---|
   | Найти работу | Нанимающих |
   | Нанять | Ищущих работу |
   | Найти ментора | Менторов, которые опытнее вас |
   | Стать ментором | Ищущих ментора, которые менее опытны |
   | Найти кофаундера | Ищущих кофаундера, с бонусом за дополняющие роли (технарь + продукт или бизнес) |
   | Обмен опытом | Тех, кто тоже пришёл обменяться опытом |

2. **Оценка.** Каждый кандидат получает взвешенную сумму:
   - роль — 34%: под вакансию, близость специализаций; для кофаундеров — дополнение ролей и взаимный поиск;
   - стек — 28%;
   - опыт — 17%: уровень вакансии, разница с ментором, опыт партнёра-CTO;
   - текст «о себе» — 11%: TF-IDF по буквенным n-граммам;
   - интересы — 10%.

   Веса выбраны по ручной разметке и кросс-валидации — [`docs/04-evaluation.md`](docs/04-evaluation.md).
3. **Понимание текста.** Из «о себе» на трёх языках извлекаются стек, интересы, искомые роли и уровень. Например, «ищем фронтенд-разработчика на React, уровень middle» превращается в React, Frontend и опыт 2–5 лет.
4. **Разнообразие.** Топ-5 собирается так, чтобы не было нескольких людей из одной компании.
5. **Объяснение и первая фраза.** Шаблоны на трёх языках заполняются фактами совпадения, поэтому объяснение всегда правдиво.

## Качество (ручная разметка 319 пар, методика — [`docs/04-evaluation.md`](docs/04-evaluation.md))

21 анкета «как у жюри»: 6 целей, 18 ролей, 3 языка. Каждая рекомендация оценена по рубрике: 0 — не подходит, 1 — можно, 2 — стоит познакомиться.

| Система | Подходящих из 5 (P@5) | «Стоит познакомиться» из 5 | nDCG@5 | Анкет с ≥ 3 подходящими из 5 |
|---|---|---|---|---|
| **MeetMatch** | **4,9** (0,98) | **3,5** (0,70) | **0,944** | **100%** |
| Без взаимности целей | 2,3 (0,46) | 2,2 (0,44) | 0,500 | 48% |
| Случайные 5 (со взаимностью) | 1,3 (0,25) | 0,6 (0,11) | 0,166 | 14% |

- **Требование кейса** — ≥ 3 подходящих из 5 — выполнено на всех 21 анкете.
- **Время подбора:** ≤ 4 мс на базе из 276 анкет (требование: < 3 с).
- **Взаимность целей:** нарушений нет, проверено для каждой анкеты базы как запроса.

Регрессионный тест `tests/test_evaluation.py` падает, если качество опустится ниже порога. Рекомендации по каждой тестовой анкете — [`reports/review.md`](reports/review.md), полный отчёт об оценке — [`reports/evaluation.md`](reports/evaluation.md).

## Запуск

### Docker

```bash
docker compose up --build
```

Откройте http://localhost:8501.

### Локально (Python 3.11)

```bash
python -m venv .venv
# Windows: .venv\Scripts\activate    macOS/Linux: source .venv/bin/activate
pip install -r requirements.txt
python -m streamlit run app.py
```

### Тесты и отчёт

```bash
python -m pytest -q                  # 47 проверок: качество, данные, бэкенд, нагрузка
python scripts/benchmark.py          # нагрузка: 276 / 1 000 / 5 000 / 10 000 анкет
python scripts/evaluate.py eval      # метрики качества → reports/evaluation.md
python scripts/review.py             # reports/review.md
python scripts/generate_profiles.py  # пересоздать базу анкет (seed=42, результат тот же)
python scripts/validate_data.py      # проверить базу: схема, правила, приватность, покрытие
```

Ключи API не нужны: сервис работает без внешних сервисов, поэтому в репозитории нет секретов.

Настройки через переменные окружения (все необязательные):

| Переменная | По умолчанию | Зачем |
|---|---|---|
| `MEETMATCH_STATE_DIR` | `./data/state` | куда сохранять отзывы и анкеты живого зала (в Docker — том) |
| `MEETMATCH_DATA_DIR` | `./data` | где лежит база анкет |
| `MEETMATCH_LOG_LEVEL` | `INFO` | подробность логов |
| `MEETMATCH_HALL` | `1` | `0` — выключить живой зал |
| `MEETMATCH_ORGANIZER_CODE` | — | Код для очистки живого зала. Задайте в окружении перед запуском. Без кода дашборд доступен для просмотра, очистка скрыта. |

  - **Покрытие:** каждую специализацию нанимают минимум 3 человека; для каждой пары «цель × роль» находится ≥ 5 подходящих кандидатов (`reports/data_profile.md`).

## Ограничения

- Объяснения строятся по шаблонам: они точные, но менее разнообразные, чем текст нейросети. LLM можно подключить поверх, не меняя подбор.
- Свободный текст распознаётся по словарю ключевых слов. Редкие формулировки и опечатки могут не распознаться; поля со списками работают всегда.
- Отзывы и живой зал хранятся в JSON-файлах (`data/state/`, атомарная запись). Для одного сервера этого достаточно; для нескольких нужна общая база данных. Подробнее — [`docs/05-backend.md`](docs/05-backend.md).
- Расписание учитывает только свободные слоты двух людей и не знает о занятых переговорках.
