## 2. Зачем этот датасет

- **Для чего:** база участников митапа, на которой Wingman подбирает знакомства. Без неё сервис не на чем показать.
- **Почему синтетика:** по условиям кейса организаторы данных не дают, а реальные профили (LinkedIn, Telegram) использовать и парсить нельзя.
- **Кто создал:** команда Wingman с помощью скрипта `scripts/generate_profiles.py`.

## 3. Состав

**Файлы:** [`data/profiles.json`](../data/profiles.json) и [`data/profiles.csv`](../data/profiles.csv) — одно и то же. В CSV списки записаны через `;`, кодировка UTF-8 с BOM, чтобы файл корректно открывался в Excel. Схема — [`data/profiles.schema.json`](../data/profiles.schema.json).

| Поле | Тип | Описание |
|---|---|---|
| `id` | строка `p001…` | идентификатор |
| `name` | строка | вымышленное имя и фамилия |
| `lang` | `ru` / `kk` / `en` | язык анкеты |
| `role` | код из 18 ролей | роль: `backend`, `data_engineer`, `lead`… |
| `experience` | целое 0–40 | опыт в годах |
| `stack` | 2–6 кодов | технологии из справочника (70) |
| `interests` | 1–4 кода | интересы из справочника (22) |
| `about` | текст 30–400 символов | «о себе» на языке анкеты |
| `goal` | один из 6 | найти работу, нанять, найти ментора, стать ментором, найти кофаундера, обмен опытом |
| `seeking_roles` | список ролей | кого ищет: только у «нанять» и «найти кофаундера» |
| `hire_levels`, `hire_exp_min`, `hire_exp_max` | | уровень вакансии: только у «нанять» |
| `company` | строка или пусто | вымышленная компания |
| `slots` | 1+ из 10 | свободное время на мероприятии |

## 4. Как собран

- **Генератор детерминированный** (`seed=42`): повторный запуск даёт ту же базу. Любое изменение видно в истории git.
- **Гарантии покрытия, а не только случайность:**
  - каждую из 14 специализаций в базе ищут работу минимум 3 человека, нанимают тоже минимум 3, ментора ищут и менторить готовы минимум 2 человека;
  - остальное распределено по популярности ролей на рынке.
- **Правдоподобие внутри анкеты:**
  - стек выбирается из реальных связок технологий для роли (например, `Python + Airflow + Spark + Kafka` у Data-инженера);
  - сфера компании попадает в интересы;
  - у ментора опыт 6–15 лет, у ищущего ментора 0–3 года, у студента 0.
- **Нанимающие:** у каждого вакансия на 1–3 роли и уровень (junior / middle / senior), стек — стек вакансии.
- **Тексты «о себе»:** 2–3 шаблона на каждую пару «цель × язык», заполненные данными анкеты; повторы исключены.
- **Имена:** вымышленные сочетания распространённых казахских и русских имён и фамилий. Для английских анкет — транслитерация.
- **Компании и стенды:** вымышлены, совпадения с реальными названиями случайны.

## 5. Проверка качества (`scripts/validate_data.py`)

| Проверка | Что ловит |
|---|---|
| JSON Schema | лишние или отсутствующие поля, неизвестные коды ролей, стека и интересов, неверные типы и диапазоны |
| 13 бизнес-правил | нанимающий без вакансии или уровня; поля вакансии у не-нанимающего; кофаундер без «кого ищу»; ментор опытом < 5 лет; студент с опытом; повторы id, имён и текстов |
| Приватность | email, телефоны, ссылки и @-никнеймы в текстах |
| CSV ↔ JSON | расхождение двух файлов |
| Покрытие «цель × роль» | для каждой роли участника и цели находится ≥ 5 взаимных и подходящих по роли кандидатов |

**Проверка самого валидатора.** В базу подбрасываются 5 дефектов: роль `astronaut`, ментор с опытом 2 года, email и телефон в тексте, вакансия без ролей, повтор имени. Валидатор ловит все 5 — это закреплено тестом `tests/test_data.py`.

Скрипт возвращает код 1 при ошибках, поэтому на шаге 7 его подключим в CI. Сломанные данные не попадут в репозиторий.

## 6. Для чего использовать и для чего нет

- ✅ **Можно:** демонстрация и проверка подбора знакомств, нагрузочные тесты, обучение команды.
- ❌ **Нельзя:** выводы о реальном IT-рынке Казахстана. Пропорции ролей и целей заданы вручную, а не измерены.

## 7. Ограничения и возможные искажения

- **Тексты шаблонные:** живые анкеты разнообразнее. Поэтому подбор опирается в основном на поля со списками, а текст даёт только 11% оценки.
- **Казахских анкет 18%.** Казахский интерфейс и распознавание текста работают, но живых казахских формулировок в базе меньше, чем русских.
- **Набор имён ограничен:** 48 имён и 22 фамилии, сочетания повторяются в разных комбинациях.
- **Нет пола и возраста в полях** — сознательно: подбор не должен на них опираться.
- **Покрытие редких сценариев.** Фаундер, который хочет стать ментором, находит только 2 подходящих подопечных. Сценарий редкий, исключён из обязательного покрытия, виден в отчёте.

## 8. Как обновить

```bash
python scripts/generate_profiles.py   # пересоздать data/*.json, data/*.csv
python scripts/validate_data.py       # проверить и обновить reports/data_profile.md
python -m pytest -q                   # убедиться, что подбор не ухудшился
```

## 9. Проверка командой

**Задание разработчику 1:** открыть [`reports/data_sample.md`](../reports/data_sample.md) — 20 случайных анкет — и отметить ✅ или ❌, правдоподобна ли каждая: роль, опыт, стек и текст сочетаются.

- отрасли отделены от тем;
- у студентов связный стек и «Изучаю» вместо «Работаю с»;
- у fullstack всегда есть фронтенд.
