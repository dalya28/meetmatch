# Шаг 4. Оценка качества подбора

> **Роль:** ML-инженер · **Дата:** 20 ноября 2026
> **Техники:**
> - ручная разметка релевантности по рубрике 0/1/2;
> - пулинг кандидатов, как на TREC, в три раунда;
> - метрики информационного поиска P@5, nDCG@5 и прямая метрика жюри «≥ 3 из 5»;
> - базовые линии;
> - абляция компонентов;
> - перебор весов по сетке с 3-кратной кросс-валидацией;
> - разбор ошибок → исправления → повторное измерение;
> - регрессионный тест качества.
>
> **Баллы, на которые работает шаг:** качество рекомендаций (30) — жюри вводит 3 свои анкеты, нужно ≥ 3 подходящих из 5.

---

## 1. Итог в одном абзаце

На 21 анкете «как у жюри» (6 целей, 18 ролей, 3 языка) Wingman в среднем выдаёт **4,9 подходящих из 5**, а **требование кейса «≥ 3 из 5» выполняется в 100% анкет**. Без взаимности целей подходят только 2,3 из 5, случайный выбор даёт 1,3 из 5.

Разбор ошибок нашёл четыре системные причины. Все исправлены, и качество выросло:
- P@5 — с 0,91 до 0,98;
- «≥ 3 из 5» — с 95% до 100%.

Подбор весов перебором по сетке переобучается. Принято только одно изменение — меньший вес интересов: оно улучшило результат на всех трёх фолдах.

## 2. Методика

### Что размечаем
- **Анкеты:** 21 из `tests/jury_profiles.json` — разные цели, роли, языки, пустая анкета, роли только в тексте.
- **Кандидаты (пулинг).** Для каждой анкеты берётся объединение топ-5 от 9 систем:
  - текущая;
  - 5 вариантов без одного компонента;
  - «только роль»;
  - случайная;
  - «без взаимности».

  Так сравнение систем честное: размечены кандидаты каждой из них, а не только нашей.
- **Три раунда.** После каждого исправления в топ-5 появлялись новые кандидаты — их доразмечали. Итого **319 пар**, неразмеченных в топ-5 текущей системы нет.

### Рубрика (зафиксирована до разметки)
| Оценка | Когда ставится | Пример |
|---|---|---|
| **2** — стоит познакомиться | Цель взаимна, роль та, что нужна (вакансия на мою роль, ментор из моей области, кофаундер с другой стороны стартапа), и есть подтверждающий факт: общий стек, подходящий уровень или сфера | Джун на Python → тимлид нанимает бэкенд junior/middle с PostgreSQL |
| **1** — можно | Роль смежная, или роль нужная, но не тот уровень или стек | Джун на Python → вакансия бэкенда middle на Go |
| **0** — не подходит | Роль не связана, или явно не тот уровень | Джун на Python → вакансия middle/senior на .NET |

Кандидат, нарушающий взаимность целей (например, соискатель для соискателя), автоматически получает 0: это прямое требование кейса.

### Метрики
- **P@5** — доля подходящих (оценка ≥ 1) в топ-5. P@5 = 0,98 означает 4,9 подходящих из 5.
- **Строгая P@5** — доля «стоит познакомиться» (оценка 2).
- **nDCG@5** — учитывает порядок: лучшие ли стоят первыми. Выгода 2^оценка − 1, нормировка на идеальный порядок.
- **«≥ 3 из 5»** — доля анкет, где подходящих не меньше трёх. Ровно то, что проверяет жюри.

Скрипт — [`scripts/evaluate.py`](../scripts/evaluate.py), разметка — [`tests/labels.csv`](../tests/labels.csv) с пояснением к каждой оценке, отчёт — [`reports/evaluation.md`](../reports/evaluation.md).

**Что это значит:**

- **Одна роль даёт 0,92 подходящих, но плохой порядок (nDCG 0,82).** Стек, опыт и текст ставят лучших наверх.
- **Интересы почти не влияют на попадание, но остаются в объяснениях.** «Общие интересы: финтех» помогают начать разговор.

## 4. Разбор ошибок → исправления

Первый замер: P@5 0,91, строгая 0,61, «≥ 3 из 5» — 95% (одна анкета не проходила). В топ-5 было 9 ошибок, все сводились к четырём причинам:

| # | Причина | Пример ошибки | Исправление | Где |
|---|---|---|---|---|
| 1 | Смежная роль засчитывалась без общего стека | Ментору по DevOps — Data-инженер без единой общей технологии | В менторстве и обмене опытом смежная роль весит вдвое меньше, если стек не пересекается | `matcher._related_only_with_stack` |
| 2 | Не учитывалось, кем человек хочет стать | Студенту «хочу стать аналитиком данных» — тимлиды на Django | Роли из текста «о себе» стали целевыми ролями участника | `matcher.prepare` → `target_roles` |
| 3 | Кофаундеры: у всех подходящих оценка роли упиралась в максимум | Фаундеру, ищущему CTO, — продакт-менеджер; лучшие не наверху | Оценка = дополнение ролей + «ищу ли я его» + «ищет ли он меня»; для CTO важнее опыт; «бизнес-кофаундер» распознаётся в тексте | `matcher._cofounder_fit`, `taxonomy` |
| 4 | Мало данных в нише | Ментору по кибербезопасности нашлось только 2 подопечных из своей области | Добор анкет: в каждой специализации ≥ 3 менторов и ≥ 3 ищущих ментора. Добавлены в конец базы, поэтому прежние id и разметка не сдвинулись | `generate_profiles.gen_niche_topup` |

**Подбор весов.**
- **Перебор по сетке переобучается.** Шаг 0,1, 1001 вариант. На отложенных анкетах подобранные веса хуже текущих: 0,895 против 0,944 nDCG@5. Значит, перебор подгоняется под 14 обучающих анкет.
- **Принято одно изменение: вес интересов 0,20 → 0,10.** Остальные веса нормированы пропорционально. Оно улучшило nDCG@5 на каждом фолде отдельно:

  | | Фолд 1 | Фолд 2 | Фолд 3 |
  |---|---|---|---|
  | Было | 0,907 | 0,896 | 0,924 |
  | Стало | 0,961 | 0,930 | 0,941 |

| Метрика | До шага 4 | После |
|---|---|---|
| P@5 (подходящих из 5) | 0,91 (4,6) | **0,98 (4,9)** |
| Строгая P@5 («стоит познакомиться») | 0,61 | **0,70** |
| «≥ 3 из 5» | 95% | **100%** |
| nDCG@5 | 0,891* | **0,944** |

\* nDCG до и после измерены на разных раундах разметки, поэтому сравнение ориентировочное. P@5 и «≥ 3 из 5» сравнимы напрямую.

**Оставшиеся 2 ошибки из 105 рекомендаций:**
- тимлиду, который нанимает Go-разработчиков, предлагается джун на PHP: Go-специалистов, ищущих работу, в базе всего один;
- ментору по кибербезопасности пятым идёт студент с Kubernetes.

## 5. Ограничения — честно

- **Один разметчик.** Оценки ставил Claude по рубрике, с пояснением к каждой. Нужна проверка командой (раздел 7): если команда не согласна с оценкой, она меняет её в `tests/labels.csv`, а метрики пересчитываются одной командой.
- **21 анкета — небольшая выборка.** Разница в 0,01–0,02 nDCG — в пределах шума. Выводы делаем только по устойчивым эффектам: взаимность, роль, стек, четыре исправления.
- **Рубрика сама по себе опирается на роль, стек и уровень.** Поэтому вывод «интересы почти не влияют» — отчасти следствие рубрики. Живые участники могут ценить общие интересы больше.
- **Синтетическая база.** На реальном мероприятии нужна обратная связь «познакомились / не подошло»: она уже собирается и видна на дашборде организатора.
